# Staying on the Keyboard: Terminal Setup for Flow

**a philosophy:** The keyboard is powerful and helps when trying to stay in the flow. Every time there is a reach for the mouse or click through a GUI menu, that breaks the flow. Moving the hand from keyboard to mouse? Context switch. Clicking through menus? Context switch. Even the tiny pause to visually locate a button adds up over the course of a day.

With AI assistants and modern command-line tools, there's a lot that can be accomplished with just a few keystrokes. Need to search files? `grep` or `rg`. Transform data? Pipe it through commands. Need help? Have your AI assistant run commands right there in the terminal—the same commands you could run yourself. A GUI isn't always necessary.

GUIs aren't evil—it's just that reaching for the terminal tends to happen more often than not. Once there's comfort with a few commands, it can be hard to go back to clicking around.

## Setting Up Your .zshrc File

If you're new to terminal customization, the `.zshrc` file is your configuration file. It runs every time you open a new terminal window. This is where you load plugins, create shortcuts, and customize your prompt.

The file lives in your home directory (`~/.zshrc`), and you can edit it with any text editor. After making changes, you can either restart your terminal or run `source ~/.zshrc` to reload the configuration immediately.

Most plugins are managed through package managers like Homebrew or Oh My Zsh, which makes installation straightforward. Once installed, a line gets added to your `.zshrc` file to enable each plugin. The setup process is usually well-documented by each tool's maintainers, so even if there's discomfort editing configuration files, step-by-step guides are available.

The approach is to start simple—add one tool at a time, test it out, and see if it actually helps. There's no need to configure everything at once. Tweaking happens over time, and small improvements keep showing up.

## z: Smart Directory Navigation

Typing `cd ~/projects/api/src/components/admin/dashboard` gets old fast.

`z` learns directory habits. It tracks every `cd` command and ranks directories using a "frequency" algorithm (frequency + recency). After a day or two of normal use, jumping to any frequently-used directory can happen with just a few keystrokes: `z api` or `z projects`. It learns where you go and gets smarter over time.

## Git Shortcuts

The git plugin is another example of efficiency gains. `git checkout -b new-feature` becomes `gco -b new-feature`. `git status` becomes `gst`. Small shortcuts that add up when used throughout the day.

## Autosuggestions and Syntax Highlighting

These two plugins are subtle but make a huge difference. **zsh-autosuggestions** shows grayed-out suggestions as you type, based on command history. Press the right arrow to accept. **zsh-syntax-highlighting** colors commands as you type—valid commands turn green, invalid ones turn red. Instant feedback before hitting enter.

Both are "set it and forget it" tools. Install them once, add them to your `.zshrc`, and they just work.

## How It All Works Together

These tools work together to keep things on the keyboard and in flow. Say there's a need to switch to a project, check what branch it's on, see what files changed, and commit them. All without leaving the keyboard:

```bash
z api
gst
gco -b new-feature
ga .
gc "Add feature"
```

No Finder windows, no Git GUI, no mouse clicks. The prompt shows the branch name at a glance. Autosuggestions remind of previous commands. Syntax highlighting catches typos before hitting enter.

Compare that to opening Finder, navigating folders, opening a Git GUI app, clicking through menus, switching back to terminal, switching back to editor... Every step is a context switch. The brain shifts from "coding" to "navigating" to "clicking" and back.

The config files (`.zshrc`, `.gitconfig`) get set up once. The commands and shortcuts get used every day. Together, they help keep hands on the keyboard and mind in the code.
